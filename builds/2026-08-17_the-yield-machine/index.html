The Yield Machine

You're a Java dev. In Java, calling a method runs it — top to bottom, then it's gone. Python's generators break that rule: a function can hand back a value, freeze in place, and thaw later with all its variables still warm. Press a button and watch one breathe.

three things to steal

      

        
    
          
  1. Calling gen() runs nothing. You get back a paused object — the work happens only when you pull.
    2. 
          
  2. next() thaws it, runs to the next yield, hands back that value, and refreezes. Every local variable is exactly where you left it.
    3. 
          
  3. Falling off the end raises StopIteration. A for loop catches that silently. Infinite generators are perfectly safe — as long as you don't force them all at once with list().
    4. 
        

      

    


    

      
the java bridge — this one's for you, knut

      

        
Java has no method that pauses mid-call. The honest equivalent is a lazy Stream:

        
Stream.iterate(new long[]{0, 1}, p -> new long[]{p[1], p[0]+p[1]})
      .mapToLong(p -> p[0])
      .limit(10)          // lazy too — but you MUST bound it
      .forEach(System.out::println);

        
Both are lazy, pull-based sequences. The Python gift: yield lets you write the logic straight down the page — ordinary loops, ordinary ifs, ordinary variables — and the language freezes the whole call frame for you. No Supplier, no builder, no hand-rolled state object. The function is the state.
