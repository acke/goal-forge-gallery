The Sticky Default 🌙

A Python function is supposed to forget everything the moment it returns. This one doesn't. Call the left one a few times — each call is fresh, you never hand it a list — and watch it quietly remember everything you ever gave it. The bug isn't in the calls. It's in the word [], and when Python decides to run it.

the trap box=[]

Type a thing, press Call. Do it three or four times. Notice you get back everything, not just the last thing.
def remember(item, box=[]):   # ← the trap lives here
    box.append(item)
    return box
what came back
# press Call…
the default object: id=… (not yet created)

the fix box=None

Same game, one changed line. This one forgets, every single time — the way you expected.
def remember(item, box=None):
    if box is None:      # make a NEW list per call
        box = []
    box.append(item)
    return box
what came back
# press Call…
the default object: None — the list is born inside the call

Why the left one leaks 🔍

When Python runs def remember(...), it evaluates the default expression [] exactly once — right then, at definition time — and staples the resulting list onto the function object as remember.__defaults__. Every call that doesn't pass box reuses that one list. There is only ever one box.

remember.__defaults__ = ( [] , )
→
the single shared list — total items ever: 0

Look up at the id= badge on the trap card: it never changes across calls. Same object, every time. On the fix card the default is just None (immutable, harmless), and a brand-new list is created inside the call — so it can't accumulate.

The one sentence to keep 🌙

Default argument values are evaluated once, when the def runs — not each time you call. Immutable defaults (None, 0, "…", tuples) don't care. But a mutable default ([], {}, set()) becomes a shared, persistent bucket hiding on the function itself.

The fix is muscle memory: default to None, then build the real thing on the first line of the body. Linters (Ruff B006, Pylint W0102) will yell about this — now you'll know exactly why.

☕ For the Java brain

Java has no default parameters, so you never trip this exact wire. But the shape is familiar: it's the same trap as a static field initialised once and shared by everything —

static List<String> box = new ArrayList<>();  // created ONCE
List<String> remember(String item){ box.add(item); return box; }

Every caller mutates the same list — a spooky-action-at-a-distance bug. Python's box=[] is that static, wearing a parameter's clothes. The mental swap: in Python the def line runs as code, once, top-to-bottom — defaults included — the way a Java static initialiser runs once.
